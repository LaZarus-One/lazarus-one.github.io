Static analysis is the art of inspecting a binary’s code, structure, and embedded artifacts without running it. It is the first phase of any reverse engineering investigation because it carries zero risk of infecting your analysis machine with malicious code.

A disciplined static triage workflow follows an established hierarchy from high-level metadata down to specific function decompilation.

The Static Triage Checklist

  1. File Identification: Confirm architecture (x86, x64, ARM), binary format (ELF, PE, Mach-O), endianness, and whether symbols were stripped (file target.bin).
  2. Shannon Entropy Calculation: Measure randomness from 0.0 to 8.0. Normal compiled code has an entropy of roughly 5.0 to 6.5. Entropy above 7.2 is a screaming red flag that the binary is packed (e.g., UPX), encrypted, or heavily obfuscated!
  3. String Analysis: Extract human-readable ASCII and 16-bit wide Unicode strings (strings -a -e l target.bin). Search for API names, C2 domains, hardcoded keys, registry keys, and error messages.
  4. Imports & Exports Inspection: Identify high-risk API imports. In Windows PE, VirtualAlloc with PAGE_EXECUTE_READWRITE often indicates shellcode injection or an unpacking stub.
  5. Cross-References (Xrefs): Jump from discovered strings or sensitive API calls directly to the basic blocks that reference them.

Spotting Cryptographic Primitives: Custom encryption algorithms are rare; adversaries and software authors almost always implement or link standard algorithms. You can identify cryptography instantly by scanning for famous hardcoded constants: AES uses the Rijndael S-box starting with 63 7C 77 7B; MD5 initializes registers with 0x67452301 and 0xEFCDAB89; SHA-256 uses initial hash constants derived from the fractional parts of square roots of the first 8 primes!
