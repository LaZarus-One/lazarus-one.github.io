When hardware Data Execution Prevention (NX/DEP) is enabled, the CPU will instantly crash if you try to execute instructions stored on the stack or heap. In 2007, researchers revolutionized exploitation with a technique that requires zero newly injected code: Return-Oriented Programming (ROP).

Instead of injecting new code, ROP scavenges existing snippets of code already present in the binary or linked libraries (like libc) that end in a ret instruction. These snippets are called ROP Gadgets.

The Geometry of a ROP Gadget

A ROP gadget is a tiny sequence of 1 to 3 instructions ending in ret (opcode 0xC3):

5f c3pop rdi ; ret; Pops 8 bytes from stack into RDI, then jumps to next gadget!

In a ROP chain, the stack acts as your program code, and the Stack Pointer (RSP) acts as your instruction pointer! Every time a gadget finishes with ret, it consumes the next 8 bytes on the stack and jumps to it.

terminal
Crafting an execve("/bin/sh", NULL, NULL) ROP Chain: To pop a root shell on Linux x86_64 without executing a single byte of injected shellcode, an attacker chains gadgets to populate registers for syscall 59:
1. pop rdi; ret → followed on stack by pointer to "/bin/sh"
2. pop rsi; ret → followed on stack by 0x0 (NULL)
3. pop rdx; ret → followed on stack by 0x0 (NULL)
4. pop rax; ret → followed on stack by 0x3b (59 = sys_execve)
5. syscall → Kernel spawns the interactive shell!

Finding Gadgets: ROPgadget and ropper

Security analysts do not manually search through gigabytes of disassembled binaries looking for gadgets. We automate gadget discovery using tools like ROPgadget or ropper:

$ ROPgadget --binary /lib/x86_64-linux-gnu/libc.so.6 | grep ": pop rdi ; ret" 0x000000000002a3e5 : pop rdi ; ret $ ROPgadget --binary /lib/x86_64-linux-gnu/libc.so.6 --string "/bin/sh" 0x00000000001d8678 : /bin/sh

By pairing a known libc memory base with these gadget offsets, an attacker constructs a complete, Turing-complete program solely out of return addresses on the hijacked stack!
