In the early 2000s, exploiting a buffer overflow was trivial: you injected shellcode directly into your stack buffer and rewrote the return address to point right back to the stack. Today, modern operating systems and compilers deploy an interlocking defense-in-depth shield known as the Exploit Mitigation Matrix.

To write modern exploits, you must understand each mitigation, how it is implemented, and the specific primitive required to bypass it.

The Anatomy of a Stack Canary: On Linux x86_64, a stack canary is 8 bytes pulled from Thread Local Storage at fs:[28h]. Notice that its lowest byte is always 0x00 (a null byte)! Why? Because string functions like strcpy, strcat, and gets terminate immediately upon hitting a null byte, making it virtually impossible to overwrite or read past the canary using string-copy functions without custom byte manipulation!

The Mitigation Status Command: checksec

Security researchers run checksec --file=target to instantly audit a binary's defenses:

$ checksec --file=lazarus_target Arch: amd64-64-little RELRO: Full RELRO Stack: Canary found NX: NX enabled PIE: PIE enabled

When all four are enabled (Full RELRO, Canary, NX, PIE), an exploit typically requires a chained two-stage attack: an information leak to defeat ASLR and bypass the canary, followed by a ROP chain to achieve arbitrary code execution.
