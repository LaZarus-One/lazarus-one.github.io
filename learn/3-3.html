3.3 Anti-Reverse Engineering & Defense Evasion

Malware authors, game developers, and commercial software vendors don't want you peering inside their binaries. They deploy Anti-Analysis techniques designed to detect debuggers, disarm sandboxes, crash analysis tools, or deliberately confuse reverse engineers.

Recognizing and neutralising these anti-analysis defenses is an indispensable skill for any offensive security researcher or malware analyst.

The RDTSC Time Bomb: The rdtsc instruction loads the CPU's 64-bit cycle counter into EDX:EAX. Malware measures the delta across a critical routine: a normal execution takes ~50 cycles, but if a human analyst single-steps or a breakpoint fires, the delta exceeds 100,000 cycles! The malware immediately alters execution flow or quietly wipes its decrypted payload.

Code Obfuscation Primitives

  1. Opaque Predicates: Conditionals whose outcome is known to the author at compile-time (e.g. x^2 + 1 > 0 is always true), but forces the disassembler to analyze both dead and live branches.
  2. Control Flow Flattening: Breaks a function's linear flow into disconnected basic blocks controlled by an artificial state variable inside a massive central switch loop.
  3. String Encryption / Dynamic API Hashing: Strings are stored as XOR-encrypted arrays and resolved on the fly using custom hash functions (e.g., ROR13) instead of cleartext API names.
