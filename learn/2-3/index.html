2.3 Control Flow Graphs & Decompilation Logic

Reading flat linear assembly files is exhausting. Modern reverse engineering tools like IDA Pro, Ghidra, and Binary Ninja represent functions as Control Flow Graphs (CFG) to make program logic immediately obvious.

A CFG breaks a function down into Basic Blocks: contiguous sequences of instructions where control enters strictly at the first instruction and leaves strictly at the final instruction, with no branches in the middle.

Interactive Control Flow Graph Anatomy

Inspect how a classic C password validation condition translates into basic blocks and branch edges:

account_tree CFG: auth_check(char *input)
CFG RECONSTRUCTED
Block 0: Evaluation
cmp dword ptr [rbp-4], 0x1337
jne loc_wrong_pass
Condition TRUE (JE taken)
mov rdi, offset s_access_granted
call puts
mov eax, 1 ; Success
Condition FALSE (JNE taken)
mov rdi, offset s_access_denied
call puts
xor eax, eax ; Failure

Reverse Engineer's Insight: Patching this binary in a debugger or hex editor requires changing a single byte: modifying 75 (JNE) into 74 (JE) or 90 90 (NOP NOP) to completely bypass the authentication check!

Recognizing High-Level Idioms in Assembly

Compilers follow predictable patterns when transforming high-level C logic into machine code:

C ConstructAssembly PatternKey Identifying Feature
if (a == b)cmp rax, rbx; jne else_labelConditional jump skips over the body block
while (x < 10)jmp check; loop: ...; check: cmp x, 10; jl loopUnconditional jump down to test, conditional jump back up
for (i=0; i<n; i++)mov i, 0; jmp test; loop: ...; add i, 1; test: cmp i, n; jl loopInduction variable incremented right before test
Dense switch(x)cmp x, max; ja default; jmp [table + x*8]Jump Table: Indirect jump through an array of code pointers
