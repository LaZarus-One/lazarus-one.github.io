4.1 Memory Corruption: Stack Buffer Overflows

C and C++ are the building blocks of operating systems and high-performance engines, but they lack native memory safety. They trust the programmer completely: if a program tells the CPU to write 64 bytes into a 16-byte stack array, the CPU blindly writes all 64 bytes, stomping over whatever happens to be sitting next door in memory.

This architectural vulnerability is the classic Stack Buffer Overflow - the vulnerability class that started modern software exploitation.

The Geometry of a Stack Smash

Recall how the stack grows downward (high to low addresses), while buffers in C fill upward (low to high addresses):

The Moment of Hijack: The crash or code redirection does not occur when the overflow happens! It occurs when the vulnerable function reaches its closing instruction: ret. The CPU pops 8 bytes from [RSP] into RIP. If those 8 bytes are 0x4141414141414141 ("AAAAAAAA"), the CPU attempts to fetch an instruction from address 0x4141414141414141, triggering an instant Segmentation Fault!
