2.2 Opcodes, Encoding & Disassembly Mechanics

Compilers translate high-level source code into machine code—a sequence of binary bytes. A disassembler’s job is the inverse: taking bytes like 55 48 89 E5 and converting them into human-readable assembly instructions like push rbp; mov rbp, rsp.

Unlike RISC architectures (such as ARM or MIPS) where all instructions are a fixed 4 bytes (32 bits), x86_64 is a Complex Instruction Set Computer (CISC) with variable-length instructions ranging from 1 byte up to 15 bytes in length!

The x86_64 Instruction Format

An x86_64 instruction is assembled from up to 6 distinct structural fields:

FieldSizeFunction & Security Relevance
Prefixes0-4 bytesLock prefix (F0), repeat prefix (F3), REX prefix for 64-bit operand sizes (48)
Opcode1-3 bytesDefines the operation (e.g. 89 for MOV, 01 for ADD, CC for INT3, C3 for RET)
ModR/M0-1 byteSpecifies addressing modes (direct register vs memory dereference)
SIB0-1 byteScale-Index-Base byte for array indexing: [base + index*scale]
Displacement0-4 bytesMemory address offset added to base
Immediate0-4 (or 8) bytesConstant hardcoded numerical operand (e.g., 0x1337)
psychology
Linear Sweep vs Recursive Traversal: Simple tools like objdump use Linear Sweep, disassembling byte-by-byte in linear order. Malware authors easily defeat this by placing an unconditional jump followed immediately by random junk bytes: the linear sweep tries to decode the junk bytes, misaligns instruction boundaries, and turns subsequent code into garbage! Professional tools like Ghidra and IDA use Recursive Traversal to only follow valid branch targets.
