1.3 Virtual Memory, Paging & Address Translation

When you run a binary, the addresses you see inside your disassembler (like 0x401000 or 0x7ffff7de2000) do not point directly to physical RAM chips. Instead, the CPU operating with the OS kernel provides every single process with an isolated illusion: Virtual Memory.

In 64-bit systems, a process has a vast virtual address space (typically 48-bit canonical addressing: 256 Terabytes), divided into user-space (lower half: 0x000000000000 to 0x7FFFFFFFFFFF) and kernel-space (upper half: 0xFFFF800000000000 to 0xFFFFFFFFFFFFFFFF).

Paging & Multi-Level Page Tables

Physical memory is split into fixed-size chunks called Frames (typically 4 Kilobytes = 4,096 bytes). Virtual memory is organized into corresponding 4 KB Pages.

The CPU's Memory Management Unit (MMU) uses multi-level page tables to map each virtual page to a physical frame on demand. On x86_64, a 48-bit virtual address is split into 5 segments:

shield
The Exploit Mitigation Anchor: The NX/XD Bit: Bit 63 of a Page Table Entry is the No-Execute (NX / XD) bit. If this bit is set to 1 by the kernel, the MMU refuses to fetch instructions from that page. When the CPU attempts to jump to stack or heap memory with NX set, hardware triggers an instant Page Fault (#PF), crashing the process and killing classic shellcode injection!
